# 認証 API

認証 API の詳細な入出力・エラー形式は [Backend API 認証仕様](../../docs/backend/api/auth.md) を参照してください。本書は実装との対応と運用上の要点をまとめます。

## エンドポイント

| メソッド | パス | 用途 | 成功 |
| --- | --- | --- | --- |
| POST | `/api/auth/login/` | Django 標準 User のユーザー名とパスワードでログイン | 200 |
| POST | `/api/auth/logout/` | 現在のサーバーセッションを無効化 | 204（空 body） |
| GET | `/api/auth/me/` | ログインユーザーと固定失効時刻を取得 | 200 |

API 認証は Django セッション認証のみです。Basic 認証、独自トークン、ユーザー登録 API はありません。業務データは認証済みユーザー間で共有され、ユーザー単位の所有権分離は行いません。

## 認証・CSRF

未認証で利用できるのは `GET /api/health/`、`GET /api/csrf/`、`POST /api/auth/login/` のみです。ログアウト、現在ユーザー取得、DRF の `/api/` 一覧、その他の業務 API は認証が必要です。認証必須 API への未認証・期限切れアクセスは `403` です。

ログイン前に `/api/csrf/` から CSRF Cookie とマスク済みトークンを取得し、ログイン POST に Cookie と `X-CSRFToken` ヘッダーを含めます。ログインおよびセッション認証を使うすべての unsafe method で CSRF 検証を行います。

## セッション期限

- ログイン時刻から 43,200 秒（12 時間）の固定絶対期限です。API 呼び出しや Django Admin の利用によって期限は延長されません。
- Django Admin を含むすべての認証セッションを期限ミドルウェアが検査します。期限情報を持たない既存セッションは無効化され、再ログインが必要です。
- `me` は `expires_at` をタイムゾーン付き ISO 8601 形式で返します。Cookie の Secure 属性等は環境設定に従います。

## 運用

Django Admin で有効な標準 User を作成してください。Compose の初期管理者固定認証情報は講義用ローカル環境向けであり、外部環境では使用しないでください。認証 API のセッション確立に対応したフロントエンドは本変更に含まれないため、現在のフロントエンドからの業務 API 呼び出しは拒否されます。
